<a id="project-overview"></a>
## 二、项目说明

A20OS 是一个面向多架构、双 ABI（应用二进制接口，规定程序与操作系统之间的二进制调用约定）的混合内核，其设计目标远超 xv6 的教学范畴，试图在单一代码库中融合 Linux 兼容层与微内核风格的 Native ABI。整体架构定位为实验型/完整 Linux 兼容型，通过分阶段初始化（boot.ref:1）串联内存、任务、文件系统等子系统，并以 init_kthread 作为内核自举与用户态引导的分界（boot.ref:2）。主要特点：一是双 ABI 并存，Linux 兼容层覆盖大量系统调用（用户程序请求内核服务的受控入口），Native ABI 引入句柄表、权限位、安全标签等微内核机制（kernel_abi.ref:1）；二是内存管理深度定制，包括 Buddy+Slab 分层、COW（写时复制，多个执行单元先共享内存页，写入时再复制） fork、swap 等（mm.ref:6, mm.ref:10）；三是网络与驱动层采用 lwIP 与 virtio（虚拟机中常用的标准化半虚拟设备接口）抽象，支持多设备类型（net.ref:5, drivers.ref:1）。这些设计表明作者追求功能广度与架构创新，但部分实现存在明显桩代码与未完成路径。

<a id="module-boot"></a>
## 三、启动流程

**模块分析：**

A20OS 的启动流程以 kernel_main() 为 C 入口，按严格顺序完成陷阱、内存、驱动、VFS（虚拟文件系统，为不同文件系统提供统一接口）、进程管理、SMP（对称多处理，多个处理器共享内存并并行运行）等子系统初始化，最终通过 init_kthread 加载并执行用户态 init 程序。具体过程是：内核 C 入口，按严格顺序初始化陷阱、内存、驱动、VFS、进程管理、SMP 等子系统，最后进入调度器或直接引导 init_kthread；PID 1 内核线程，负责打开 init 程序、加载 ELF、校验入口映射、构造用户栈并创建用户态 init 进程。

<a id="module-mm"></a>
## 四、内存管理

**模块分析：**

该内核的内存管理子系统采用 Buddy 物理页分配器 + Slab 对象缓存 + 三级页表（记录虚拟地址到物理地址映射关系的数据结构） (Sv39（RISC-V 指令集架构的 39 位虚拟地址分页模式）) + VMA（虚拟内存区域，记录一段进程虚拟地址空间的范围、权限和用途）虚拟内存区域管理的分层架构。具体过程是：初始化 Buddy 分配器，构建 RAM 段空闲链表并标记内核占用页；分配物理页，order-0 走 CPU 本地批次，高阶走 buddy 锁内分裂；Slab 分配入口，小对象走缓存，大对象走 buddy 高阶路径；释放 Slab 对象，做多重校验后归还空闲链表或释放页面。

**实现位置：** [`kernel/mm/frame.c:177-187`](#evidence-E-MOD-mm-bf26446828)、[`kernel/mm/frame.c:292-308`](#evidence-E-MOD-mm-874bf34694)、[`kernel/mm/slab.c:28-39`](#evidence-E-MOD-mm-ff2470a885)、[`kernel/mm/slab.c:432-444`](#evidence-E-MOD-mm-92b286c412)

<a id="module-task"></a>
## 五、进程与任务调度

**模块分析：**

本模块实现了一个多核 SMP 调度器，核心抽象是 per-CPU 运行队列 proc_runq_t（8 级队列，第 0 级为 RT FIFO/RR（时间片轮转调度，各任务按固定时间片轮流运行），第 1 级为 EEVDF 公平调度列表）与 task_t 任务结构。具体过程是：时钟中断处理，为当前任务记账并检查时间片是否耗尽；为新任务选择负载最低的 CPU，考虑亲和性掩码；请求目标 CPU 重新调度，必要时发送 IPI；销毁任务，从运行队列摘除并释放资源。

**模块分析：**

## 八、进程间通信
