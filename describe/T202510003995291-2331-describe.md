<a id="project-overview"></a>
## 二、项目说明

该仓库是 arceos-starry 家族下的一个实验型 Linux 兼容内核，以 Rust 实现，旨在提供较完整的 POSIX（一组类 Unix 操作系统接口标准）系统调用（用户程序请求内核服务的受控入口）接口。整体架构采用模块化设计，包含启动流程、内存管理、进程调度、文件系统、信号、IPC（进程间通信，指不同进程交换数据和同步状态的机制）、网络、驱动和系统调用层等模块，并复用 ArceOS 的 axhal/axmm 等基础设施。与 xv6 等教学内核相比，它显著扩展了系统调用覆盖面（212 项），并引入了进程组/会话模型、动态 ELF 加载、信号跳板、设备内存直映射等复杂机制，但许多高级特性仍为桩实现或存在明显简化。最值得评审注意的特点：一是系统调用层通过 `handle_syscall` 统一分发，并利用 `syscall_trace` 过程宏自动生成日志，但非法 syscall 号被静默映射为 `memfd_secret`，可能掩盖错误；二是内存管理采用 per-CPU 用户内存访问标记区分内核态访问用户内存的缺页，但 I-cache 刷新未实现；三是文件系统采用自研 VFS（虚拟文件系统，为不同文件系统提供统一接口）框架，支持挂载点树和多种伪文件系统，但 inode（文件系统中记录文件属性和数据位置的索引节点）回收依赖脆弱的引用计数魔法数字。

## 三、启动流程

**模块分析：**

本模块以 src/main.rs 的 main() 为入口，完成根文件系统切换、挂载、文件描述符表初始化后，通过 run_user_app() 创建用户地址空间、加载 ELF 可执行文件、构造 UspaceContext 并生成用户任务交给调度器。具体过程是：内核启动入口，完成根文件系统切换、挂载与 FD_TABLE 初始化后调用 run_user_app；创建用户地址空间、加载 ELF、构造用户上下文并生成任务交给调度器，返回退出码；读取可执行文件，支持 ELF 与 #! 脚本递归加载，返回入口地址与栈顶；解析 ELF 程序头，对每个 PT_LOAD 段分配物理页并写入段数据。

## 四、内存管理

**模块分析：**

本仓库内存管理以 axmm 的 AddrSpace 为核心抽象，在 core/src/mm.rs 中封装了用户地址空间创建、ELF 加载、信号跳板映射和用户内存访问标记。具体过程是：创建空的用户地址空间，以 USER_SPACE_BASE 为基址，供进程创建时初始化地址空间；将 ELF 文件的 LOAD 段映射到用户地址空间并写入段数据，返回入口点和 auxv 向量；完整加载用户应用：读文件、处理脚本/解释器、映射 ELF/栈/堆、构造参数区域，返回入口和 SP；在闭包执行期间标记当前为内核访问用户内存上下文，允许缺页处理按用户访问处理。

<a id="module-task"></a>
## 五、进程与任务调度

**模块分析：**

本模块实现了一个 POSIX 风格的两级进程层次（Session→ProcessGroup→Process→Thread），核心抽象是 Process/Thread/ProcessGroup/Session 四个结构体及全局表 PROCESS_TABLE/THREAD_TABLE/PROCESS_GROUP_TABLE/SESSION_TABLE。具体过程是：创建无父进程的新生进程（如 init），同时创建新会话和新进程组；创建子进程，继承父进程的进程组，父进程引用指向调用者；进程退出，将子进程移交给 reaper，标记 zombie；回收 zombie 进程，从父进程、进程组、进程表移除。
