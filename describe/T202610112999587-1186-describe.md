<a id="project-overview"></a>
## 二、项目说明

该仓库是一个面向 RISC-V64 与 LoongArch64（龙芯使用的 64 位指令集架构）双架构的、从零实现的实验型微内核，家族血缘标注为 unknown，但代码深度远超教学型 xv6 衍生品。它采用 workspace 组织，包含 28 个 crate，核心抽象包括 StartContext 启动交接、KernelMemorySubsystem 分层分配器、Arc&lt;Task&gt; 调度实体、VFS 与双文件系统、完整 POSIX（一组类 Unix 操作系统接口标准）信号、SysV IPC（进程间通信，指不同进程交换数据和同步状态的机制）、用户态网络栈、异步块驱动框架、表驱动 系统调用（用户程序请求内核服务的受控入口）分发、以及 native-abi（应用二进制接口，规定程序与操作系统之间的二进制调用约定）/elm/soyo/kcsan 等自研库。整体定位是探索型内核，试图在保持 Linux ABI 兼容的同时引入微内核风格的能力机制与模块化设计。最值得评审注意的三个特点：一是启动流程通过 StartContext 实现架构无关交接，并动态发现内存而非固定布局；二是内存管理采用七层分层分配器，将锁顺序作为第一公民，并引入分配记账与审计；三是调度器以 Arc 为任务身份，实现 EEVDF 多调度类与 PI 优先级继承，远超 xv6 的 round-robin。

## 三、启动流程

**模块分析：**

启动流程以 `StartContext` 为平台无关交接对象，由架构加载器（RISC-V（一种开放指令集架构）/LoongArch）在完成早期页表（记录虚拟地址到物理地址映射关系的数据结构）、临时栈、BSS 清零后构建，再交给 `__kernel_start_init` 分派到 DTB/ACPI 路径。具体过程是：RISC-V 物理地址入口，裸汇编搭建 Sv48 最小页表并切换地址空间；清零 BSS、采集启动参数、初始化 per-hart（RISC-V 中可独立执行指令的硬件线程）数据，必须在写静态变量前调用；完成 DTB 快照、日志绑定、启动分配器初始化并构建 StartContext。

## 四、内存管理

**模块分析：**

## 五、进程与任务调度

**模块分析：**

本模块以 Arc&lt;Task&gt; 为最小调度实体（对应 Linux task_struct），不分配全局整数 PID 表，任务身份即 Arc 指针，父子关系通过 Weak/Arc 互引。具体过程是：主动让出 CPU，从当前核 runqueue 挑出下一个 eligible 任务并切换，返回时调用方已重新获得 CPU；结束当前线程，控制流不返回，调用 exit_task 后 drop 自身 Arc 再 schedule_once；按 pgid 查找进程组对象，先从 session 内查找，失败则从 pid namespace 存活任务线性扫描反查。
