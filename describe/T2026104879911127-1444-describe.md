<a id="project-overview"></a>
## 二、项目说明

该仓库是一个面向 Linux 兼容性的教学/实验型内核，基于 ArceOS 的 axhal/axtask/axmm 等模块构建，通过 starry-api 和 starry-core 两层抽象实现系统调用（用户程序请求内核服务的受控入口）、进程管理、内存管理、文件系统、信号、IPC（进程间通信，指不同进程交换数据和同步状态的机制）、网络和驱动框架。整体架构定位为“Linux 兼容型教学内核”，旨在覆盖尽可能多的 POSIX（一组类 Unix 操作系统接口标准）系统调用（190 项），但许多实现是简化或桩代码，适合教学演示而非生产使用。主要特点：一是通过编译期注入命令行参数实现评测与调试路径的静态分流，确保评测确定性；二是采用双层任务模型（Thread/ProcessData）模拟 Linux 进程组/线程组语义，并通过 extern_trait 宏将用户线程注入内核任务扩展槽；三是内存管理通过 Backend 枚举统一匿名页、COW（写时复制，多个执行单元先共享内存页，写入时再复制）、文件映射等，并实现了完整的 mmap（把文件或匿名内存区域映射到进程虚拟地址空间的接口）族系统调用，但部分高级功能（如 mremap）仍是桩实现。系统调用覆盖：190 项系统调用中约 40% 是桩或简化实现，fork/execve/futex（快速用户空间互斥量，内核为用户态同步提供的等待与唤醒机制）路径存在非空实现，但 mremap/madvise/seccomp 等直接返回成功或未实现。

<a id="module-task"></a>
## 五、进程与任务调度

**模块分析：**

本仓库的进程与任务调度模块以 axtask 提供的 TaskInner 为底层调度原语，在其上构建了 Thread/ProcessData 两层抽象：Thread 封装线程级状态（信号、定时器、robust list、clear_child_tid），ProcessData 封装进程共享资源（地址空间、文件描述符作用域、资源限制、futex 表）。具体过程是：实现 clone/fork/vfork 系统调用，根据 CLONE_THREAD 标志决定创建线程还是进程；线程退出主路径：处理 clear_child_tid、robust list、通知父进程、清理共享内存。
